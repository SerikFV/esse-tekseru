# tekSER

Қазақ тіліндегі эссені **нақты Google Gemini API** арқылы талдайтын веб-қосымша.
FastAPI + Python 3.12, HTML/CSS/JavaScript, PostgreSQL 17, SQLAlchemy және Uvicorn.
Дайын талдау, кездейсоқ балл немесе offline fallback қолданылмайды. API кілті жоқ
болса, сайт түсінікті қате көрсетеді және талдау жасалғандай нәтиже шығармайды.

## Іске қосу

Python 3.12+ және PostgreSQL орнатыңыз (Docker Compose немесе жергілікті сервер). Барлық команданы
репозиторийдің түбірінен орындаңыз. Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m scripts.prepare_local
```

Linux/macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m scripts.prepare_local
```

Скрипт `.env` файлын жергілікті PostgreSQL үшін кездейсоқ құпиясөзбен жасайды,
бар файлды өзгертпейді. Құрылым үлгісі — [`.env.example`](.env.example).

1. [Google AI Studio](https://aistudio.google.com/apikey) арқылы Gemini кілтін алыңыз.
2. **Тек сервердегі `.env`** файлында `GEMINI_API_KEY=` жолына кілтті енгізіңіз
   немесе осы атаумен сервердің құпия орта айнымалысын орнатыңыз.
   Кілтті чатқа, frontend-ке немесе Git-ке жібермеңіз.
3. Қажет болса, `GEMINI_MODEL` мәнін өз аккаунтыңызға қолжетімді, structured JSON
   және суреттерді қолдайтын Gemini моделіне ауыстырыңыз. Әдепкі: `gemini-3.5-flash-lite`.
4. Деректер базасын іске қосыңыз:

```sh
docker compose up -d --wait db
```

Windows:

```powershell
.venv\Scripts\python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Linux/macOS:

```sh
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Жергілікті браузерде `http://127.0.0.1:8000` мекенжайын ашыңыз. Frontend-ті
`file://` арқылы бөлек ашудың қажеті жоқ: оны backend береді. API құжаттамасы: `/docs`.
`.env` немесе кілт өзгергеннен кейін серверді қайта іске қосыңыз.

Бұрынғы орнатуды жаңартқанда `.env` ішіндегі `GEMINI_MODEL` жолын да тексеріңіз:

```dotenv
GEMINI_MODEL=gemini-3.5-flash-lite
```

Процестің орта айнымалысы `.env` мәнінен басым. Ескі модель әлі қолданылса,
PowerShell-де серверді бастар алдында `$env:GEMINI_MODEL="gemini-3.5-flash-lite"`
орнатыңыз. `/api/health` жауабындағы `model` нақты қолданылған модельді көрсетеді;
кілттің мәні бұл endpoint арқылы қайтарылмайды.

Docker орнына орнатылған PostgreSQL қолдануға болады: `esse` базасы мен сол базаға
ғана рұқсаты бар пайдаланушы жасаңыз, `.env` ішіндегі `DATABASE_URL` мәнін
`postgresql+psycopg://USER:PASSWORD@HOST:5432/DB` форматына ауыстырыңыз.
Арнайы таңбалары бар құпиясөзді URL-encode жасаңыз. Compose іске қосу қажет емес.
Кестелер startup кезінде жасалады. Базаға уақытша қосылу қатесі болса, API қайта тексереді.
Бұл бастапқы схема; болашақ схема өзгерістеріне migration қажет.

## Аккаунттар, Gmail және алғашқы әкімші

Басты бет ашық. Эссені талдау, OCR, тарих, салыстыру және қайта тексеру үшін
расталған аккаунт қажет. Оң жақтағы адам белгісі `/auth` бетін ашады; кіргеннен
кейін профиль мәзірі көрсетіледі. `/profile` — жеке кабинет, `/admin` — әкімшіге ғана
рұқсат етілетін басқару API-лерін пайдаланатын бет. Жеке эсселерді әкімші де басқа
адамның аккаунты арқылы аша алмайды; панельде жиынтық көрсеткіштер мен қателер бар.

Gmail-де екі қадамды растауды қосып, `https://myaccount.google.com/apppasswords`
арқылы **қолданба құпиясөзін** жасаңыз. Сервердің Git-тен жасырылған `.env` файлына:

```dotenv
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USERNAME=YOUR_EMAIL@gmail.com
SMTP_PASSWORD=YOUR_GOOGLE_APP_PASSWORD
SMTP_FROM_EMAIL=YOUR_EMAIL@gmail.com
SMTP_FROM_NAME=tekSER
SMTP_SSL=false
COOKIE_SECURE=false
```

`SMTP_USERNAME` және `SMTP_FROM_EMAIL` бір жіберуші Gmail мекенжайы болуы керек.
Қолданба құпиясөзін көрсетілген топтар арасындағы бос орындарсыз енгізіңіз.
Бұл SMTP құпиясөзі тек хат жіберуге арналған; сайт аккаунтының құпиясөзі бөлек.

Жаңарту кезінде серверді Ctrl+C арқылы тоқтатып, Windows PowerShell-де:

```powershell
git pull
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m scripts.setup_admin
```

Баптау пәрмені әкімші логинін (әдепкі `admin`), email, сайтқа арналған құпиясөзді
және оны қайталауды сұрайды. Құпиясөз экранда көрінбейді және файлға жазылмайды.
Поштаға келген кодты енгізгеннен кейін ғана аккаунт пен әкімші құқығы құрылады.
Бар аккаунтты алғаш әкімшіге айналдырғанда оның құпиясөзі және поштасы тексеріледі.
Бұрын әкімші тағайындалса, пәрмен оның деректерін қайта жазбайды.

Содан кейін серверді қайта қосыңыз:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Сайтта Ctrl+F5 басып, әкімші email/логині және сайт құпиясөзі арқылы кіріңіз.
Linux/macOS-та осы пәрмендердегі Python жолын `.venv/bin/python` деп ауыстырыңыз.

Қалыпты тіркелуде логин 3–30 латын әрпінен, саннан немесе `_` белгісінен тұрады.
Логин мен email регистрге тәуелсіз бірегей. Құпиясөздің **жалғыз күрделілік талабы —
кемінде 4 таңба**; бос орындары автоматты қиылмайды, сан/бас әріп/арнайы белгі
міндетті емес. Қайталау өрісімен дәл сәйкестік тексеріледі. Құпиясөздер scrypt
арқылы жеке salt-пен хэштеледі. Email пішімі тексерілгені оның расталғанын білдірмейді.

Поштаға алты таңбалы код жіберіледі. Аккаунтты растауға дейінгі сұрау бөлек
`email_challenges` кестесінде сақталады, `users` жазбасы тек код дұрыс болғанда
құрылады. Код 10 минут жарамды, ең көбі 5 рет тексеріледі, қайта жіберу аралығы
60 секунд. Жаңа код бұрынғы сұрауды жарамсыз етеді. Сәтсіз SMTP жіберуде аккаунт
немесе жарамды challenge құрылмайды. IP/mailbox/login лимиттері PostgreSQL-де
сақталады және бірнеше worker арасында ортақ. Ескірген уақытша деректер жаңа
сұраулар кезінде тазартылады; қолданушыға аяқталмаған тіркелу құқығы берілмейді.

Сессиялар кездейсоқ токенмен жасалады; базаға токеннің тек хэші сақталады,
браузерде HttpOnly/SameSite cookie қолданылады. Жазатын API сұрауларында
`X-Requested-With: tekSER` тақырыбы және бірдей Origin қажет. Құпиясөзді қалпына
келтіру/ауыстыру және бұғаттау бұрынғы сессияларды жарамсыз етеді. Email өзгерісі
жаңа пошта расталғанша күшіне енбейді. Интернеттегі HTTPS орнатуда
`COOKIE_SECURE=true` және нақты `SITE_URL=https://your-domain.example` орнатыңыз.

Бұрынғы эссе кестелері өзгертілмейді: иелер жаңа `essay_owners` кестесіне жазылады.
Бұрынғы ортақ жұмыстар аккаунттарға өздігінен таратылмайды және жойылмайды.
Жергілікті базаңыздағы сол жұмыстарды әкімшіге бекіту үшін алдымен санын қараңыз:

```powershell
.\.venv\Scripts\python.exe -m scripts.claim_legacy --username admin
```

Бұл тек алдын ала қарау. Деректер сізге тиесілі болса, нақты көшіруді орындаңыз:

```powershell
.\.venv\Scripts\python.exe -m scripts.claim_legacy --username admin --apply
```

Әкімші логині басқа болса, `admin` орнына соны жазыңыз. Басқа пайдаланушыға
бекітілген жұмыстар өзгермейді; пәрменді қайталау бұрын көшірілгендерді қоспайды.

## Нақты AI жұмыс ағыны

«Эссені талдау» → эссені PostgreSQL-ге сақтау → екі бөлімді фондық тексеруге
жіберу → дайын бөлімді жеке транзакцияда сақтау → интерфейсте біртіндеп көрсету.
Frontend `POST /api/essays/analyze?background=true` арқылы 202 жауап пен эссе ID алады,
содан кейін сол эссенің күйін оқиды. Бетті жабу тексеруді тоқтатпайды. Дайын баға
тақырып тексеруі сәтсіз болса да сақталады; тек сәтсіз бөлімді қайта тексеруге болады.

| Критерий | Максимум |
|---|---:|
| Құрылым | 25 |
| Аргументация | 30 |
| Логика | 20 |
| Дәлелдер | 15 |
| Тілдік сапа | 10 |
| Барлығы | 100 |

Баллдар бүтін сан болуы керек. Шектен тыс, теріс, жол түріндегі баллдар,
толық емес JSON және эсседе кездеспейтін дәйексөздер қабылданбайды. AI-дың жалпы
баллы қолданылмайды. Маркерлер балл қоспайды: олар тек контекст. Стиль мен түр
100 балдық жүйеден бөлек анықталады. Табылмаған құрылымдық элемент интерфейсте
«Анықталмады» деп көрсетіледі. Статистика мен дәйексөздердің сыртқы шындығы тексерілмейді.

Gemini-ге ықшам output schema беріледі: типтер, міндетті өрістер, enum және сандық
балл шектері сақталады; үлкен жол/массив көлем шектері осы провайдер схемасынан
алынады. Толық Pydantic валидациясы backend-те өзгеріссіз орындалады, оның ішінде
4000/2000 таңба шегі, тізім ұзындығы және барлық балл шектері. Күрделі толық схема
нақты API-де `400 INVALID_ARGUMENT` берген; ықшам схема `200` жауабын алды.

### Тақырыпқа сәйкестік және әділ баға

Екі бөлек AI сұрауы қатар орындалады:

1. **Эссе сапасы:** модельге тек мәтін мен көмекші маркерлер жіберіледі.
   Пайдаланушы енгізген тақырып бұл сұрауға қосылмайды. Бес критерий мәтіннің
   өз негізгі ойына қатысты бағаланады, жалпы балл серверде қосылады.
2. **Тақырып сәйкестігі:** модель тақырыпты мәтінмен салыстырып, `matched`,
   `partial`, `mismatched` немесе `undetermined` мәртебесін, қазақша себебін
   және түпнұсқадан дәйексөздерді қайтарады. Ішінара/мүлде сәйкес келмесе,
   мәтінге лайық басқа тақырып ұсыну міндетті.

Сәйкестік үшін балл шегерілмейді, жалпы баға нөлге түсірілмейді және шектелмейді.
Өте әлсіз мәтін өз сапасы бойынша төмен не нөл балл алуы мүмкін. Модель жауаптары
ықтималдыққа негізделгендіктен, қайталанған талдауларда аздаған айырма болуы мүмкін.
Ұсыныс бастапқы тақырыпты автоматты өзгертпейді. Тақырып тексеруінде AI түпнұсқаның
нөмірленген үзінділерін таңдайды; сервер дәйексөздерді мәтіннен өзі алады. Модельдің
дәйексөзді байқамай түзетуі немесе қайта тұжырымдауы енді осы бөлімді бұзбайды.
Бұрынғы тарих жазбалары да ашылады. Оларда жоқ тақырып тексеруін бағасын өзгертпей толтыруға болады.

### Қателер, қайта тексеру және нұсқалар

- Әр бөлімде `pending`, `ready`, `failed` күйі бар. Жалпы күй: `pending`, `ready`,
  `partial`, `failed`. Жұмыс істемеген бөлімге жалған нәтиже немесе нөл балл қойылмайды.
- Әр дайын бөлім бірден сақталады. «Тек осы бөлімді қайта тексеру» дайын бөлімді
  қайта шақырмайды. Бір мезеттегі екі retry PostgreSQL row lock арқылы бір ғана AI
  әрекетін бастайды. `request_id` UUID қайталанған жіберуден қорғайды.
- Сервер тоқтаса, жұмыс үзіліп қалғаны көрсетіледі. Күтпеген тоқтауда pending lease
  timeout + 30 секундтан кейін аяқталады; дайын бөлімдер қалады. Жаңа retry-ды ескі
  жұмыс нәтижесі алмастыра алмайды. Бұл — сол Uvicorn процесінде жүретін фондық
  тапсырмалар; бөлек durable task queue қолданылмайды.
- Жаңа `essay_workflows` кестесі startup кезінде автоматты жасалады; бұрынғы
  кестелер мен деректер өзгертілмейді. База пайдаланушысына жаңа кесте жасау рұқсаты керек.
- «Ұсыныстар бойынша түзету» бастапқы мәтінді сақтап, жаңа нұсқаны оның `parent_id`
  байланысымен талдайды. Салыстыруда мәтіннің қосылған/алынған тұстары, бес критерий
  айырмасы, аргументтер, дәлелдер және бұрынғы/қазіргі ескертулер көрсетіледі.
  Бұрынғы нұсқаны жою басқа нұсқаларды жоймайды, бірақ оның салыстыру байланысын үзеді.
- Баға айырмасы автоматты түрде жақсару дәлелі емес. Өзгерген үзінді де «қате
  міндетті түрде түзелді» деп белгіленбейді. Түсініктемелер мен жаңа мәтінді салыстыру қажет.

### Мәтіндегі ескертулер

AI нақты әлсіз үзінділерге `text_feedback` қайтарады; тілдік түзетулер де ескеріледі.
Backend әр үзіндіні бастапқы мәтінге бекітіп, Unicode код-нүктелері бойынша
`start/end` орнын, санатын, түсіндірмесін және ұсынысын береді. Ойдан шығарылған
үзінділер қабылданбайды. Бірдей үзінді бірнеше рет кездессе, алғашқы орны белгіленіп,
қайталау саны көрсетіледі. Қабаттасатын ескертулерді бір белгіден бірге ашуға болады.
Белгіні басу немесе Enter/Space арқылы ашу түсіндірмені көрсетеді; «Осы үзіндіні
түзету» жаңа нұсқа режиміне өткізіп, редактордағы орнын таңдайды. Мәтін автоматты
ауыстырылмайды. Түзету жіберілгенде пайдаланушы келісімді қайта белгілейді.

Тарих бастапқы мәтінмен және толық JSONB нәтижесімен сақталады. Кілт frontend-ке
қайтарылмайды, Google-ге URL параметрі емес, `x-goog-api-key` тақырыбымен беріледі.
Талдауға тұтас 90 секунд timeout (кезек пен жауапты түзету уақыты бірге), 3 қатар AI сұрау шегі, quota/permission/network/JSON қателері
үшін қазақша хабарламалар бар. Қате кезінде жалған нәтиже сақталмайды.
JSON құрылымы, балл немесе үзінді тексеруі өтпесе, модельге қате өрістермен бірге
алдыңғы жауабы беріліп, бір рет түзету сұралады. Уақытша 500/502/503/504 қатесінде 2 және 4 секунд
кідіріс бар. Бір бөлімге барлығы ең көбі үш API сұрауы, 90 секундтық ортақ шек беріледі
(екі бөлімге әдетте екі, ең көбі алты сұрау). Әр жауап қайта тексеріледі.
Авторизация/квота қателері автоматты қайталанбайды; 429 қатесінен кейін қайта тексеруге
60 секунд күту керек. Бөлім қатесі сақталған күйде көрсетіледі, басқа нәтиже жоғалмайды.

Қолжазбаны тану үшін JPEG/PNG/WebP суретін таңдаңыз (8 МБ, 20 мегапиксельге дейін).
Gemini суреттен мәтінді таниды; мәтінді тексеріп, түзеткеннен кейін ғана талдаңыз.
Тану дәлдігі кепілденбейді. Суретті жіберу алдында келісім сұралады, сурет базаға сақталмайды.

## Дизайн

Editorial стилі: жылы ақ фон, қою қызыл акценттер, нөмірленген критерийлер,
қағазға ұқсас редактор және бір стильдегі талдау, ескертулер мен нұсқаларды салыстыру.
Noto Sans және Noto Serif қаріптері серверден беріледі; сыртқы font сервисі қажет емес.
Қазақ әріптері бар WOFF2 нұсқалары және SIL Open Font License мәтіндері
`frontend/assets/fonts/` ішінде. Жаңартылған CSS/JS мекенжайларындағы нұсқа параметрі
бұрынғы дизайнның браузер кэшінен жүктелуін болдырмайды.

## API

Аккаунт API: `/api/auth/me`, `/register`, `/validate`, `/verify`, `/resend`, `/login`,
`/forgot`, `/logout`, `/logout-all` (соңғы атаулар `/api/auth/` префиксімен).
`GET/PATCH/DELETE /api/account`, `POST /api/account/email`, `POST /api/account/password`.
Әкімші API: `/api/admin/overview`, `/users`, `/pending`, `/services`, `/audit` және
`PATCH /api/admin/users/{id}` арқылы бұғаттау. `/auth`, `/profile`, `/admin` HTML
беттерінде жеке деректер болмайды; деректер тек қорғалған API арқылы алынады.
Рұқсат қателері: 401 — кіру қажет, 403 — құқық/Origin, 404 — эссе бұл аккаунтқа тиесілі емес.

| Әдіс | Мекенжай | Міндет |
|---|---|---|
| POST | `/api/essays/analyze` | `title`, `essay_text`, қосымша `parent_id`, `request_id` → сақталған күй (201) |
| POST | `/api/essays/analyze?background=true` | Эссені сақтап, тексеруді фонға жіберу (202) |
| GET | `/api/essays?limit=20&offset=0` | Соңғы талдаулар (limit: 1–100) |
| GET | `/api/essays/{id}` | Мәтін мен толық нәтиже |
| POST | `/api/essays/{id}/retry/grade?background=true` | Тек сәтсіз бағалауды қайталау |
| POST | `/api/essays/{id}/retry/topic?background=true` | Тек сәтсіз/бұрын орындалмаған тақырып тексеруін қайталау |
| GET | `/api/essays/{id}/versions` | Осы нұсқа және оның алдыңғы нұсқалары (ең көбі 100) |
| GET | `/api/essays/{id}/comparison?before_id=1` | Алдыңғы нұсқамен мәтін мен бағаларды салыстыру |
| DELETE | `/api/essays/{id}` | Эссе мен талдауды жою → 204 |
| POST | `/api/ocr` | Multipart `image` → танылған мәтін |
| GET | `/api/health` | База және кілттің бапталу күйі (құпия мәнсіз) |

`/api/health` кілттің **бар-жоғын** ғана тексереді: нақты API авторизациясын,
quota немесе модельдің қолжетімділігін растау үшін live тест қажет.
Қателер: 422 — кіріс/сурет, 429 — retry күту мерзімі, 409 — бір request_id басқа
мәтінге қолданылған, 503 — база, 404 — табылмады. Сақталған эссенің AI қателері
`sections.grade.error` / `sections.topic.error` өрістерінде болады; HTTP 201/202
талдаудың толық дайын екенін білдірмейді. `status` пен бөлім күйлерін тексеріңіз.

## Тексеру

Offline тексерулер және нақты PostgreSQL roundtrip (AI орнына **тек тестте**
бақыланатын жауап қолданылады):

```sh
.venv/bin/python -m pytest -q
RUN_DATABASE_TESTS=1 .venv/bin/python -m pytest -q
node --check frontend/script.js
```

PowerShell:

```powershell
$env:RUN_DATABASE_TESTS="1"
.venv\Scripts\python -m pytest -q
```

База тесттері бірегей оқшауланған schema жасайды және соңында жояды;
қосылған пайдаланушыда `CREATE SCHEMA` рұқсаты болуы керек. Негізгі кестелер өшірілмейді.

Браузердегі толық E2E (қосымша Playwright құралы, тестте ғана AI fixtures):

```sh
python -m pip install -r requirements-browser.txt
python -m playwright install chromium
python tests/browser_smoke.py
```

Скрипт `.venv` Python ортасымен жеке FastAPI серверін іске қосып, PostgreSQL-де
оқшауланған schema жасайды және соңында жояды. `APP_PYTHON` арқылы басқа Python,
`CHROMIUM_EXECUTABLE` арқылы орнатылған Chromium жолын беруге болады. Сервердің
8002 порты бос болуы керек. Бұл тест Gemini-ге сұрау жібермейді.

**Нақты Gemini + PostgreSQL интеграциясы** (API quota жұмсалады):

```sh
.venv/bin/python -m scripts.verify_live
# 13 сценарий: эссе сапасы, стильдер, қысқа мәтін және тақырып сәйкестігі
.venv/bin/python -m scripts.verify_live --suite
# Тек бір сценарийді қайталау:
.venv/bin/python -m scripts.verify_live --case "өте қысқа"
.venv/bin/python -m scripts.verify_live --case "тақырып сәйкес емес"
.venv/bin/python -m scripts.verify_live --case "тақырып ішінара сәйкес"
```

Windows-та `.venv/bin/python` орнына `.venv\Scripts\python` пайдаланыңыз.
Скрипт шынайы Gemini-ді шақырып, нәтижені сақтау/қайта оқу/жоюды тексереді.
Кілт жоқ болса `BLOCKED`, exit code 2; қате болса exit code 1. Ол mock жауаппен
алмастырылмайды. Suite тек механикалық дұрыстық пен бірдей емес бағаларды тексереді;
академиялық әділдік пен жіктеу сапасын оқытушы бөлек бағалауы керек.

Автоматты тексерулер нақты PostgreSQL және бақыланатын AI жауаптарымен орындалады:
жеке бөлімді сақтау/қайта тексеру, қатар келген submit/retry, сервер тоқтауы,
ескі жұмыс нәтижесінің жаңа әрекетті алмастырмауы, бұрынғы тарих, нұсқалар,
Unicode орнын белгілеу және мәтін/балл салыстыру. Браузерде толық цикл тексерілді:
ішінара нәтиже → reload → тек тақырыпты retry → белгіден түзету → жаңа нұсқа →
салыстыру → қайталанған жіберуден қорғаныс → телефон өлшеміндегі интерфейс.

Аккаунттарды енгізгеннен кейін **106 автоматты тест өтті**: пошта расталмайынша
пайдаланушы құрылмауы, кодтың мерзімі/әрекет саны/қайта жіберуі, бір мезеттегі
растаулар, бірегей логин/email, сессияны аяқтау, құпиясөзді қалпына келтіру,
әкімші құқықтары, жеке эсселер және ескі деректерді қауіпсіз бекіту тексерілді.
SMTP адаптерінде TLS → login → хат жіберу реті тексеріледі. Толық браузерлік
сценарий тіркелу → код → жеке эссе/нұсқалар → профиль/құпиясөз/email өзгерісі →
қалпына келтіру → әкімші бұғаттауы және телефондағы көріністі қамтиды.
Бұл тексеруде пошта мен AI adapter-лері тесттік; нақты Gmail жеткізілімі туралы
қорытынды жасалмайды. Жаңа беттер: [скриншоттар](docs/design/README.md).

Нақты API-де толық бағалау схемасы `400 INVALID_ARGUMENT`, ал ықшам схема `200`
қайтарғаны салыстырылып тексерілді. `gemini-3.5-flash-lite` арқылы толық браузерлік
жұмыс ағыны өтті: әдейі қателері бар кітап оқу эссесі 49/100 алды, 4 тілдік түзету
және 6 бекітілген мәтіндік ескерту сақталды; түзетілген нұсқа 92/100 алды. Екі
нұсқа PostgreSQL-ден қайта оқылып, мәтін мен бес критерий салыстырылды. Бұл — нақты
AI жауаптары, fixture емес. Осы мәндер тұрақты эталон немесе бағалау әділдігінің
статистикалық дәлелі емес. Әр бөлімнің нақты моделі сақталады; әртүрлі модельмен
бағаланған нұсқаларды салыстыруда арнайы ескерту шығады.

`gemini-3.1-flash-lite` осы тексерулерде жүктеме қателерін қайтарғандықтан әдепкі
модель `gemini-3.5-flash-lite` болып жаңартылды. Бұрынғы `.env` және сыртқы орта
айнымалылары автоматты өзгермейді. Жаңарту кезінде модель жолын бөлек тексеріңіз.
Баспа қазақша мәтін OCR-ы бұрын тексерілген; қолжазба дәлдігі жеке расталмаған.
Бұрынғы `gemini-2.5-flash` моделі осы аккаунтта жаңа пайдаланушылар үшін жабық
болғандықтан ауыстырылды. AI бағалары ықтималдыққа негізделген: қайталанған
сұрауларда балл өзгеруі мүмкін. Академиялық бағалау сапасын оқытушы тексеруі керек.

## Деректер мен орналастыру

- Эссе Gemini-ге талдау үшін жіберіледі; интерфейсте келісім белгісі бар.
- `.env` Git-тен алынып тасталған, `.env.example` ішінде құпия жоқ.
- Тарих, нұсқалар және нәтижелер аккаунт бойынша бөлінеді. HTTPS орнатуда Secure
  cookie, Origin, proxy request body шегі және сыртқы rate limiting баптаңыз.
- Аккаунттар мен SMTP адаптері автоматты тексерулерден өтеді; браузерлік тесттерде
  email/AI жауаптары тек оқшауланған тест серверіндегі adapters арқылы беріледі.
  Нақты Gmail жеткізілімі жергілікті `.env` баптауымен `scripts.setup_admin` арқылы
  расталады. Тест кодтары мен mail fixture endpoint-тері production қолданбада жоқ.
- PostgreSQL Docker volume ішінде сақталады. `docker compose down` деректерді
  қалдырады; **`docker compose down -v` базаны жояды**. Cloud task арасындағы
  тұрақты сақтау үшін басқарылатын PostgreSQL және backup қолданыңыз.
- Тек `.venv` мен файлдардың сақталуы процестердің қайта қосылатынын білдірмейді:
  жаңа ортада PostgreSQL мен Uvicorn-ды қайта іске қосыңыз.
- API кілтін алу және квотаны қосу — Google AI Studio аккаунтында орындалатын
  әрекеттер. Қолжетімді болмаса, қолданба жалған талдау көрсетпейді.
